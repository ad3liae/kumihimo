# Task 018: `everyRegionCarriesTheRidgeIncludingBothEdges` が2分かかる

- 状態: **完了**（2026-09-12）。**243秒 → 22秒。**ユニット全体 442秒 → 202秒。**例外は閉じた**
- 優先度: 低
- 起点: Task 007H の検証（`AGENTS.md`「60秒を超えるテストは作りを疑う」に該当）

## 症状

`everyRegionCarriesTheRidgeIncludingBothEdges` が **118.98 秒**（007H）。007G 時点で 131.86 秒
だったので、**007H が持ち込んだ遅さではない。** テスト単位の上限 60 秒で打ち切られ、300 秒で
通る。

## 調べること

1. 何に時間がかかっているか。全頂点に対して「素の輪郭からの起伏」を計算しているなら、
   頂点数 12 万に対して1頂点あたりの計算が重い可能性がある。
2. **主張を弱めずに**速くする。標本を間引くなら、間引いても同じ欠陥を捕まえられることを
   示すこと（わざと縁の畝を消して落ちることを確認する）。
3. 直せないなら、`@Suite(.timeLimit(.minutes(3)))` を**このテストだけ**に付け、理由を
   コメントに書く。既定の上限を上げないこと。

## やらないこと

- テストを消すこと、`@Test(.disabled)` にすること。
- 全体の上限を上げて隠すこと。

---

## 結果（2026-09-12）

### 記録が倍に古かった

**実測は2分ではなく 4分3秒（243秒）だった。** この文書の題と、`AGENTS.md` の
「1件だけ上限を上げてあるもの」と、テスト自身の doc comment が、そろって「2分ほど」と
書いていた。**Task 007H の 118.98 秒から倍に伸びていたが、誰も気づいていなかった。**

**気づけなかった一因は、費用の形が取り違えて書いてあったことである。**
doc comment は「メッシュ全頂点を4回歩く」と書いていた。**そうではない。**
`reliefFromThePlainOutline` が、**1頂点ごとに 4領域 × 257 段 = 1028 点の断面外形を
引き直していた**。しかも `Flat16SurfaceMesh.crossSectionPoint` は安い関数ではなく、
呼ぶたびに弧長の表を歩く。

**費用が「頂点数 × 4」と書いてあれば、頂点が増えたときに伸びるのは当たり前に見える。**
実際は「頂点数 × 1028 × 弧長表」だった。**間違った形で書かれた費用は、伸びても誰にも
見えない。**この文書の「調べること 1」は頂点あたりの計算が重い可能性を正しく疑っていたが、
doc comment のほうを信じると疑う理由が消える。

### 直したこと

**外形をループの外へ出しただけである。**`plainOutline` を suite の `static let` にして、
1028 点を全体で1度だけ作る。**外形は測る点に依存しないので、結果は変わらない。**
**領域と段の順序も元の二重ループのままにしてある**ので、等距離の2点のどちらが選ばれるかまで
同じである。**主張は1つも弱めていない**（間引いていない。`調べること 2` の「標本を間引くなら
わざと縁の畝を消して落ちることを示す」は、間引いていないので不要）。

`調べること 3`（直せないなら `@Suite(.timeLimit)` を付ける）は**使わなかった。直ったからである。**

### 例外を閉じた（2026-09-12、作者の指示による）

**`@Test(.timeLimit(.minutes(5))) を外し、`-maximum-test-execution-time-allowance` も渡すのを
やめた。**この 300 はこの1件のために上げた値だったので、**例外が消えれば書類も消える。**
**いまリポジトリに `.timeLimit` は1つも無い。**

**23秒に5分の上限を残さないのは、締めるためである。**上限が実測よりはるかに高いと、
**次に10倍伸びても上限に当たらず、また見えなくなる。**60秒で落ちるほうがよい。

`-maximum-...` は**数を選び直すのではなく、渡すのをやめた**（`xcodebuild -help` は既定値を
書いていないので、**勘で数を置かずに既定へ戻した**）。どの試験も `.timeLimit` を宣言していない
ので、**全件が `-default-test-execution-time-allowance 60` で頭打ちになる。**

**外した状態で1回走らせて確かめた**（`-only-testing:KumihimoTests`、
`-test-timeouts-enabled YES -default-test-execution-time-allowance 60` のみ）:

- **412件成功・0件失敗・4件スキップ、打ち切り 0件、ビルド警告 0件**
- **60秒を超えた試験は1件も無い。**最も遅いのは当の
  `everyRegionCarriesTheRidgeIncludingBothEdges` の **22秒（上限の37%）**、次が11秒、9秒、8秒
- **テスト段階 202秒**（上限を付けていた前回の実行は212秒。差は実行ごとのぶれの範囲）
- **ハッシュは3つとも不変**（`theRoundBraidsMeshIsTheShapeItWas`、
  `theFlatBraidsMeshIsTheShapeItWas`、`theMeshIsTheShapeItWas`）

`AGENTS.md` の「1件だけ上限を上げてあるもの」の節は**消さずに、閉じた記録に書き換えた**
（旧状態・なぜ上げていたか・なぜ閉じたか）。**同じことをもう一度やらないための記録であって、
いま守るべき決まりではない**と断ってある。**6 の「Task 018 の2分のテスト」も直した。**
