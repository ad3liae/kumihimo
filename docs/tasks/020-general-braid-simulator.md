## このプロダクトの目的（作者の言葉）

> このプロジェクトの目的は、伝統的な編み方で模様を組む前から知ることができるのはもちろん
> だけど、編み方を自分で編み出せる組紐シミュレータなんだよ。
> 丸台だけではなく他の角台などもサポートさせたい、だから一般化しないといけない。

**組み方ごとの専用コードを書く方向はここで終わりにする。** 台と手順列を入力として、組み上がりを
導く一般の道を作る。丸源氏と平源氏は、その道への**2つの入力**であり、検証のための既知解である。

## これまでに分かっていること（読んでから始めること）

### 組み方とは何か

台には糸の位置がある（丸台なら16、4面に4つずつ）。組み方とは「どの位置の糸をどの位置へ
動かすか」の手順の列で、1周期で配置が元に戻る（糸の入れ替わりを除く）。丸源氏と平源氏の
手順表は3冊の本で照合済みで、`MaruGenjiSimulation` / `HiraGenjiSimulation` にある。

### 手順列だけから導けること（位相構造）

- どの糸が長手方向に留まり（縦糸）、どの糸が横切るか（横糸）
- 横切る糸がどの列の下を通るか。**手順の順番が組み点での上下を決める（あとに動かした糸が上）**
- 各糸が周期の中のどの瞬間にどの位置へ着くか（到着の位相）
- 断面の並び（糸の本数と役割から）

**これは実際に導いてあり、検証も通っている。** `HiraGenjiWeaveDerivation` がこれをやっている
（名前は平源氏専用だが、中身の大半は一般である）。bookA p97 の3つの配色実験——横糸だけに色
→本体が無彩色、内側の対と外側の対→縁取りが矢絣、奥と手前で2色→表裏反転のはしご——は、
手順表から導いた通り道に色を乗せただけで本の記述どおりに出た。**これが組み方のシミュレー
ションであり、描画とは無関係である。**

### 手順列だけからは導けないこと（寸法）

1手でどれだけ紐が伸びるか（模様の縦横比）、糸がどれだけ盛り上がるか（畝）、断面がどれだけ
潰れるか。これは糸の太さ・張力・組み点での詰まりで決まる。Task 016 で、完成品の釣り合いから
は出ず、組み点を解く必要があり、それは解けなかったことが分かっている。

**既知の組み方については資料の写真から測ってある**（下表）。**自分で編み出した組み方には
写真が無い**ので、同じ糸・同じおもりの既知の組み方から**持ち回る**。推定値であることを隠さない。

### 導出の前提（Task 021 で確認済み、2026-09-07）

**通過する糸は、通る列で長手方向に糸の太さ d を占める。** 着地だけで数えると（k=1）、同じ d の
中に横糸2本と縦糸1本が重なり、**非貫入が満たせない**（残差が 0.42 前後で止まり動かない）。
通過層を含めると（k=3）残差は単調に減り続ける。**引きの大きさを10倍ずつ振っても変わらない。**

したがって **pitch = k × d、平源氏 0.375（実測 0.3665、+2.3%）は導出として立つ。**

## 作るもの

### 1. 台（Stand）

位置の集合と、その空間配置。丸台（16、4面）、角台、その他。**位置の配置が断面の周の並びを
決める**（丸台なら角度の順）。8玉・12玉・16玉を同じ型で扱う。

### 2. 組み方（Method）

台の上の手順列。1手＝位置から位置へ（対で動かすものは対で）。1周期と、周期末の詰め直し。
丸源氏・平源氏の既存の手順表がそのまま入ること。

### 3. 導出（Derivation）— 本体

台と組み方から：各糸の軌道、縦糸／横糸の分類、通り道、上下（手順の順番から）、到着の位相、
断面の並び。**組み方の名前に依存するコードを1行も書かない。** `HiraGenjiWeaveDerivation` の
中身を一般化して移す。

### 4. 見え方（Views）

導出の結果を見せる。**2つあり、どちらも導出の結果だけを読む。**

- **模様図（2D）**：どの糸がどこを通り、どこで上下し、何色か。**寸法の推定を含まないので、
  自分で編み出した組み方に対して正確な答えになる。** これが「編み出す」ための本体の見え方。
- **立体（3D）**：糸として描く。寸法（3.で導けないもの）を別に受け取る。007J で作りかけた
  糸のビルダー（`BraidStrandSegment` / `HiraGenjiStrandPath` / `HiraGenjiStrandMeshGenerator`）
  がこの種である。**組み方ごとの生成器を持たない。**

### 5. 寸法（Shape）

既知の組み方は測った値。編み出した組み方は持ち回りの推定値。**どちらであるかを表示する。**

### 手順表の対称性から導けたこと（実測）

|  | 手の集合を保つ反射 | 回転 | `9-p` の軌道 |
|---|---|---|---|
| 平源氏 | `1-p`, `9-p` | 8のみ（2回対称） | 8個 |
| 丸源氏 | `1-p`, `5-p`, `9-p`, `13-p` | 4, 8, 12（4回対称） | 8個 |

`9-p` の軌道 `[1,8][2,7][3,6][4,5][9,16][10,15][11,14][12,13]` は、現行の平源氏の断面の
**厚み方向の対と完全に一致する**。`positionThroughTheBraid` は式で書く必要がなく、手順表から
導ける対称性である。**縁がどれかも手番から出る**: 平源氏の手1・手2 の行き先 13/12 と 4/5 が
ちょうど縁の2組である。

**導出できないものが1つある**: 残り3組（列0/5・列1/4・列2/3）の幅方向の並び順。対称性は

bookA p96 がこれを与えている。

### 承認した型

- **`BraidStand`** は位置の集合、周に沿った巡回順、天板上の実座標だけを持つ。**群（北/東/南/西、
  角台の辺）は手順表を書くための呼び名であり、導出は触らない。**
- **`BraidMethod`** は位置→位置の手の列。糸は状態が運ぶ。**終状態を持たず、適用して求める。**
- **`BraidCrossSection`** は表裏・縁を case に持たず、**糸1本ずつの巡回列**で表す。
- **導出は `BraidShape`（寸法）を受け取らない。** 関数の引数に無いことで保証する。

### 判断1: 断面の幅方向の並び順 → 宣言された入力とする。ただし既定を決める

- **導出の既定の断面は「台の周の巡回順そのもの」（筒）とする。** 丸源氏はこれで済む。
- **平たく畳むのは物理の結果であり、導出の外である。** よって平源氏の畳み方（どの対が外側か）は
  `source: .reference("bookA p96")` の宣言された断面になる。
- **編み出した組み方は、畳み方を宣言しなければ筒として出る。隠さずそう表示する。**
- **`BraidSlot.isTurningSlot` は導出の出力である。宣言させない。** 宣言させると平紐の概念が
  入力へ戻る。

### 段階1.5（段階2の前に、データだけで確かめる小さな項目）

**「現行の断面＝台の周の順に、組み点での交差を1つ加えたもの」ではないか。** bookA p96 で
入れ替わるのは隣り合う2位置（板位置1と2）であり、これは交差1つがすることそのものである。

- 両方の組で成り立てば、**畳み方の宣言が不要になる。**
- 成り立たなければ、**「畳み方は入力」と確定する。**
- どちらでも前進である。**段階1では追わない。**

### 判断3: 丸源氏の8が一致しないときの扱い

合わせ込まない。**ただし「Task 004 の手写しの表と一致しない」ことだけでは、導出が誤りだと

出方）であって、表そのものではない。

1. Task 004 の64升の表（1升ずつ）。
2. 写真で検証した配色の出方。`.build/task005e-references/` の bookA p94・p95 の作例と、

対 手番の規則）も同様に、両者が違ったら両方を報告し、写真と作者の実物で決める。

- 対の一方は**組み移動が着地する場所**、他方は**閉じ移動でしか到達しない場所**である。

### Task 004 の over/under は観測ではない（確認結果、2026-09-07）
