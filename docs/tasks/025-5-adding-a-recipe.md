# Task 025-5: レシピを1つ足す手順

- 状態: **手順書**（2026-09-09 作成）。実装の指示書ではない
- 前提: `docs/architecture.md`「初期リリースはレシピのある紐に限る（作者の決定）」、
  `docs/tasks/025-initial-release-rendering.md`（とくに「025-4 の判定」と「025-4 の 3」）

**レシピは3つでできている**——**手順表・配色・測った形の値。**
**平らな紐はこれに加えて紐のまわりの並び順を宣言する**（Task 020「判断1」の、既定つきの
宣言入力）。**3＋1 であって、発明ではない。**

置き場所は `Kumihimo/Domain/BraidMethodCatalog.swift`。**組み方の名前が入ってよい唯一の場所**
である（`sh Scripts/check-braiding-is-general.sh` が他を見張っている）。

## 1. 手順表を写す（bookC の記法）

bookC は32ノッチのディスクで、1サイクルを**刷られた順の番号つきの手**で書いている。

1. **休むノッチと台の位置の対応**を図の開始図から読む（`BraidMethodCatalog.diskRestingNotches`
   と同じもので、Fig.20 と Fig.32 は同じ番号づけである）。
2. **手を刷られた順にそのまま並べる。** 順序は飾りではない——**あとに動かした糸が上になる。**
3. `BraidDiskNotation` に入れる。`threadsPerStep` は**bookA/bookB の刷られた手が何本を
   一度に運ぶか**（源氏系は2）。**手順の単位は bookC の1手＝1本である。**
4. **詰め直しの手は自分で印を付けない。** `isRepositioning` が**1ノッチの移動**で見分ける
   （源氏系2表では、最短の組みの手と最長の詰め直しのあいだに10ノッチの隙がある）。
   **短い組みの手を持つ紐では、ここを読み直す必要がある。**

**検算**: `BraidRecipe.worked(on:)` が `nil` を返さないこと。返したら**表がその台の
1サイクルになっていない。**

## 2. 配色を書く

**台の4つの群（north / east / south / west）に、本が並べる順（外側から）で色を並べる。**
`BraidMethodCatalog.colouring(on:_:)` がそれを位置ごとの割り当てに直す。
**書いていない位置はカタログの既定色になる。**

**配色は、その紐を本が写真に撮っている配色を採るのがよい**（丸源氏は bookA p94、
平源氏は bookA p96）。**判定できるものを選ぶこと。**

## 3. 測った形の値を持ち込む（007 系の手順）

**測り方の正本は `docs/measurement-procedures.md`。新しい測り方を作る前に読むこと。**

| 量 | 測り方 | 例 |
|---|---|---|
| 断面 幅÷厚み | 周長＝糸の本数、厚み＝2本で解く | 平源氏 3.3359 |
| 1手のピッチ÷紐幅 | 資料の写真から（測り方2.5の遠近補正つき） | 平源氏 0.3665 |
| 山の高さ | 輪郭のさざ波（測り方2）＋物理 | 平源氏 0.45 |
| 山形の密度 | 紐幅を揃えて並べて数える（測り方3） | 丸源氏 1.8〜2.15 |

**必ず `.observed` として、出どころ（本・ページ・タスク番号）を添えて入れる。**
**「d に対する比」なら `basis: .threadDiameters`** と書く——**構成が使えるのはこれだけで、
別の単位からの換算はしない**（換算を発明した時点で測定値ではなくなる）。
**帯でしか分からないなら `spread:`**、**単独では確かめられていないなら `unsettled:`** に
その旨を書く（丸源氏の山 0.12 と縦横比 0.65 は**積だけが写真に縛られる**）。

**見た目に合わせた数を `.observed` にしないこと。** 目で合わせた数は `.declared` で、
**「写真に対して目で較正した、導出ではない」と必ず書く。**

## 4. 平らな紐は並び順を宣言する

**平らな紐の環は台の縁の順とは違う**（平源氏は `[14, 16, 15, 2, 1, 3, …]`）。
`BraidCrossSection(order:source:)` に**出どころつきで**宣言する。
**畳み方は宣言しない**——`BraidFold` が環と糸の道すじから導く。
**管の紐は何も宣言しない**（台の縁の順が既定で、それが管である）。

## 5. 族の判定と、**合う描き手が無ければ描かない**

**族は紐から読む**（`BraidFamily.family(of:)`）——**畳めるなら平ら（面の列数つき）、
畳めないなら筒**、それに糸数。`BraidFamilyDrawing` が族に合う描き手へ渡し、
**合う描き手が無ければ `nil` を返す。教わっていない紐を間違って描くよりよい。**

**いま描き手があるのは2つの族だけである**——**平ら16本（面6列）と丸い筒16本。**
**他の族（8玉、12玉、角台）には描き手が無い。** 模様図（2D）は族に関わらず出る。

### 平らな描き手の制約（**判断 (b)、2026-09-09**）

> **平らな描き手は到着の位相を bookA の時計（1手＝2本）で受け取り、左の縁が中心化の
> 折り返しの境界（−0.5）にちょうど乗っている。一般の導出は bookC の時計で数えるので、
> 平らなレシピを次に足すときは、先に中心化を本体中心の対称な折り返しに直し（頂点の移動を
> 測って報告）、そのうえで bookC の時計を渡す。**

**それまで、平らな族は平源氏のレシピ以外を `nil` にする**
（`Flat16SurfacePatternGenerator.drawsOnlyTheRecipe`）。
**bookC の時計へそのまま移すと、0.0385 段の差が 0.9615 段として描かれ、紐が長手に
最大 12.80 d ずれる**（`tasks/025-initial-release-rendering.md`「bookC の時計へは、
まだ移せない」）。

## 6. 検算

**架空の紐の試験がこの手順の検算である**——`KumihimoTests/BraidRecipeIsThreeThingsTests`
と `KumihimoTests/BraidFamilyDrawingTests`。**bookC の Fig.32 を1/4回転した表**を
3つ（手順表・配色・測った値1つ）だけ与え、

- **導出・図・積みのどれにも手を入れずに通る**こと
- **族が紐から読めて、丸い筒の描き手がメッシュを返す**こと
- **平らな紐では並び順を宣言すること**（`aFlatBraidDeclaresItsOrderRoundTheBraid`）

を確かめている。**新しいレシピを足したら、同じ3つを自分の紐で確かめること。**
