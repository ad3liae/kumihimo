## 1. 縦線

**原因。**到着の位相を入れたとき（Task 032）、最初の行の升（前のリピートで始まっている）を**帯の端で2つに切り、
下の切れ端を上端へ回していた。**端面を平らに保つためだったが、そのせいで**全てのレーンがタイルの端に升の境目を
持つ**ことになった。サムネイルではリピートごとに全高を貫く線、立体では升の境目が紐を一周する位置になる。
**Task 030 と同じ形**（端だけ例外にしていた）。

**直し方。切らない。**最初の行の升は前のリピートから描く。位相はレーン全体への定数の足し算なので、レーンは
厳密に1リピートの長さのままで、最後の升は次のリピートの最初の升が始まる所で終わる（**タイルは厳密に周期**）。
はみ出しは、サムネイルでは**枠が切る**（リピートはもともと枠の両端をはみ出して描かれ、`clipShape` が切っている）。
立体では次のタイルと噛み合う。**新しいクリップは書いていない。**Task 032 で入れた切れ端の撚りの筋の取り分
（`stripeRange`）は、切れ端が無くなったので外した。

**テスト（直す前に落ちることを確かめた）:**

| テスト | 直す前 | 直した後 |
| --- | --- | --- |
| `noCellBoundaryRunsTheFullHeightOfTheCard`（枠 1300×208、隣り合うレーンが同じ長手位置に升の端を持たない） | レーン 0 と 1 がリピートの継ぎ目ごと（213.5 pt 周期）に端を共有 | 共有なし |
| `noRingOfCellEndsGoesRoundTheSolid`（メッシュの頂点ブロックから升の両端を読む） | x = −3.095、0.0、+3.095（タイルの両端とリピートの継ぎ目）で共有 | 共有なし |

（立体の試験は最初、三角形と升の対応を取り違えて余計な一致を拾っていた——`triangleSegmentIndices` は作った順、
`allTriangleIndices` は色ごとに並べ直した順。頂点ブロックで読むように直してから、落ちることを確かめ直した。）

- タイルの端が平らでなくなったので、閉じの試験（`oneRepeatClosesAndMakesNoEndFace`）と筋の継ぎ目の試験は
  **レーンごと**にした: どのレーンもちょうどタイル1枚の長さで、終わる頂点の輪は始まる輪をタイルの長さだけ
  動かしたもの
- 裏面を捨てるカメラの試験（Task 032）は、タイルの端を「一番遠い頂点」から取っていたため、1枚のタイルの端の
  ぎざぎざ（設計どおりで、次のタイルが埋める）で 5,760 本中 14 本の背景を拾った。**タイル自身の半長**から
  15% 離れるように直した（不透明の試験と同じ取り方。1レーンが短くなるのは最大1サイクルで、それより広い）

**一覧のカード（直した後、シミュレータで見た）。**八つ金剛S のカードは8レーンの升が端から端まで煉瓦積みにずれ、
**全高を貫く線は無い。**カードの各列（横 987 px）で、升の輪郭の暗い画素が高さの何割を占めるかを数えると、
最大 0.36（全高を貫く線なら 1 に近くなる）。

**立体の輪（直す前）。**升の境目はタイルの両端とリピートの継ぎ目で全レーン揃っていた。ただしこの時点では升の端に
形が無く（畝は1本に続き、色も筋も継ぎ目で連続していた）、**目には輪として出ていなかった。**2. で升の端を丸くすると
そこに紐を一周する溝が出るはずだった。1. を先に直したのはそのためである。

## 2. 升の両端

- **同じレーンで隣り合う升の境目で、畝は谷底まで下がり、次の糸の升がそこから始まる。糸の端は丸い。**
  列を横切る畝の断面 `crestProfile`（半楕円。`RoundTube16SurfaceMesh` から借りたもの）を端のまわりに回した:
  高さ = `crestProfile(√(across² + e²))`、`e` は端から糸の半幅のあいだで 1 → 0。**新しい数は無い**
  （丸みの長さは糸自身の半幅）
- 長手の標本は、横の標本と同じく `crossSectionOffset`（同じく借りたもの）で両端に寄せた
- **遮蔽も升の両端に効かせた**（16本の数を4辺に。平源氏の目 `Flat16StitchTexture.shading` と同じ使い方で、
  数は増えていない）。保留していた理由（位相が無いと1サイクルごとに暗い輪が出る）は、到着の位相で端が
  ずれたので消えた
- **谷の深さ 0.282 は変えていない**
- テスト: `aCellEndsInAGrooveAndItsEndIsRound`（升の両端の輪は谷底、升の真ん中は畝の頂、各升は同じレーンの次の升が
  始まる輪で終わる）、`theShadingIsTheSixteenThreadTubesValley`（4辺）。外向きの巻き・不透明・裏面を捨てるカメラの
  試験は、升の端を入れても通る

**一周する輪は出ていない。**シミュレータの既定の縮尺で、見えている4レーンの暗い点（升の端）は1サイクル
（約 94 px）ごとに出るが、**4レーンが同じ長手位置で暗くなる所は無い。**

**見え方の変化（谷の深さ）。**升の端が入って初めて、長手方向にも谷 0.282 が効くようになった。比較シート
（写真と同じ紐幅）の描いた紐の輪郭は、さざ波が紐幅の 0.05（正面）〜0.10（30° 回して）、周期 0.40〜0.43
（1サイクル）。写真の輪郭のさざ波は 0.025（段階1、測り方2。丸い紐には使えないと 005J が結論した下限）。
**谷は写真より深く見える。値は据え置きの判定のまま。**

**豆は粒に見えるか（判断）。粒には見える。**レーンごとに丸い粒が並び、隣のレーンとは煉瓦積みにずれ、両方向に溝が
ある——「色を塗り分けた8本の棒」ではなくなった。**ただし写真の豆とは形が違う**: 写真の豆は長く、斜めに傾き、
端がすぼまって隣と重なって見える。描いた粒は長さと幅がほぼ同じ（1サイクル 0.40 × 1列 0.38）で、まっすぐ立った
丸いドームで、真珠を並べたように見える。**傾き（段階1 の単位の傾き）と縦横比はここでは触っていない。**
比較シートの塗り手は糸ごとに1色で陰を付けないので、粒は輪郭の波にしか出ない。粒の判断はシミュレータの
描画で、写真と同じ紐幅に並べて行った。

## 3. 縦の谷を浅くした（作者の判定、2026-09-12）

**判定**: 判定 (2) の「谷の深さは据え置き」は**横の谷（レーン間の 0.282）についての判定**であって、縦の谷には
及ばない。**縦は導出されていない——横の 0.282 を流用しただけで、流用は導出でも測定でもない。**縦の谷に別の名前を
与え、`.declared` として「写真に対して目で較正した、導出ではない」と書く。横の 0.282 は触らない。端の丸みも短くし、
隣の升と少し重なって見えるところまで。物理の言い分も doc comment に書く。

**入れた数（2つとも `.declared`、`RoundTube8SurfaceMesh`）:**

| 名前 | 値 | 何に対する比 |
| --- | --- | --- |
| `endValleyDepthRatio` | **0.18** | 紐の外半径。**横の `crestHeightRatio` 0.282 とは別物**（流用をやめた） |
| `endRoundingOverHalfWidth` | **0.55** | 糸の半幅。丸める長さ（前は 1.0 ＝ 半幅いっぱいで、升が球になっていた） |

**物理の言い分**（doc comment に書いた）: 同じ位置に前後して立つ2本は、後の1本が組み点で束の上に置かれ、
**下の錘に引かれて前の1本へ押し付けられる**ので、糸半分ぶんの谷は空かない（`architecture.md`「組み台の力学」）。
**横に並ぶ2本にはそれが無い**——外向きの張力で並んでいるだけなので、横の谷のほうが深い。

## 4. 残っている差: どうやれば良さそうか（**未着手・判定待ち。実装していない**）

**見た目の調整はここで打ち切り**（作者、2026-09-12）。`endValleyDepthRatio` 0.18 と
`endRoundingOverHalfWidth` 0.55 は据え置きで、**これ以上数字を動かさない。**以下は手を付けずに書いた見通しであり、
**着手には判定が要る。**

### 4.1 いま何が違うか（数で）

| | 描いたもの | 写真 |
| --- | --- | --- |
| 升の形 | **0.403（長手）× 0.393（幅）**——ほぼ正方形 | 豆は**細長い** |
| 升の向き | **軸に平行**（1つも傾いていない） | **斜めに寝ている**（段階1 の最短の歩幅で +36.0°） |
| 隣との関係 | 端で接し、少し重なって見える程度 | **隣と重なって見える**（端がすぼまって差し込まれている） |
| 色の帯 | 向きによって +36.5〜+63.0°（16通り、ぼかし 61） | **+54.5°**（1つの向き） |

長手 0.403 は測った伸び（`.observed`）、幅 0.393 は「周を糸の本数で割る」から出る（`π/8`）。
**どちらもこの節で動かす対象ではない。**

### 4.2 一番有力な筋: 留まっている区間の**両端の周方向**を使っていない

前提（`docs/architecture.md`「組み台の力学」）は、留まっている糸について
**「到着の長手座標から出発の長手座標まで」**と言っている。いまの実装はその**長手座標だけ**を使い
（到着の位相＝Task 032、出発は次の到着で代用）、**両端が周のどこにあるかを使っていない。**

糸は前の位置から来て次の位置へ去る。**到着の瞬間、その糸はまだ前の位置の側にあり、出発の瞬間にはもう次の位置の
側へ動き始めている。**したがって留まっている区間は厳密な軸平行ではなく、**両端が周方向へ振れた、寝た紡錘**に
なるはずである。中央（いちばん強く留まっている所）が自分の位置に立ち、両端が隣へ寄る。

- **これは「前提を曲げる」ではなく、「前提が言っていて実装が使っていない」ほうである**——到着の位相、升の両端と
  同じ形の指摘。Task 032 段階2 の仕分けでいえば 1 ではない
- **傾きと、投影で見かけが伸びるぶんの長さが同時に動く可能性がある。**両端が周方向に振れれば升は寝て、
  面に投影された姿は長手方向に長く見える——写真の「細長い・斜め・隣と重なる」の3つが1つの原因から出る筋である
- **振れ幅は前提から一意には出ない。**「到着の瞬間にどれだけ前の位置側にいるか」は、渡りが束に押し込まれる
  深さの話であり、**そこが解釈である。だから判定待ちとする**
- 触る所は升の形そのもの（`RoundTube8SurfacePattern` の `centerlineStart` / `centerlineEnd` の周方向、および
  それを畝にする `RoundTube8SurfaceMesh.frame`）。**`columnsCarriedPerCycle`（3コマ）も占有履歴も動かさない**——
  どの糸がどこに立つかは変わらず、**立っている区間の形だけが変わる**

### 4.3 先に要る測り直し

**中心帯ではなく、円筒の縮みを戻して全幅で測る**（Task 032 の持ち越し、`docs/measurement-procedures.md`）。
8列の紐は**中心帯が1列ぶんしか無く、読みが紐の向きで量子化される**（描いたものの色の帯は 16通りで
+36.5〜+63.0° に振れた）。**いまの 36.0°／54.5° は、その穴を持ったままの値である。**
形を動かす前に、この測り方で写真と描いたものを測り直すこと。順序を逆にすると、何に合わせたのか分からなくなる。

### 4.4 波及

- **形が動けば、`endValleyDepthRatio`（0.18）と `endRoundingOverHalfWidth`（0.55）の2つの `.declared` は
  較正し直しになる。**寝た紡錘では端の見え方が変わるので、いまの2つはその形に対しては較正されていない
- 「升は1つも傾いていない」を固定しているテスト（`theColourDiagonalIsRecordedAgainstThePhotographs`）と、
  S と Z の鏡像のテストは、主張を書き直すことになる
- 八つ金剛のハッシュは動く。丸源氏・平源氏は動かない
