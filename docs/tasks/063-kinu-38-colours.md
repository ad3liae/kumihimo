## 1. いまの作り（審査側が読んだ）

- `ThreadColorCatalog`（`Kumihimo/Domain/ThreadColor.swift`）: 12色。`ThreadColor` は `id`・`name`・`temporaryCode`（K-01 など）・`value`。
  既定の色は `natural`（生成り）。
- 保存: 作品は糸ごとに `ThreadColorID` の文字列を持つ（`ThreadAssignment`）。**古いIDの作品が端末に残っている。**
- 色を ID の文字列で直接書いている所: `BraidMethodCatalog` の見本配色（丸源氏・平源氏・八つ金剛S/Z・返し・丸四つ・江戸八つ）、
  `ProjectEditorPreviewData`、`YatsuKongoComparisonPreview`、`ThreadColorColorIDs`。
- **試験が色の数と並びに頼っている**: `ThreadColorCatalog.colors[$0 % ThreadColorCatalog.colors.count]` の形が
  `Flat16SurfaceMeshTests`・`Flat16VisibleThreadTests`・`Flat16CardAgreesWithSolidTests`・`BraidSurfaceWatertightnessTests`・
  `MaruGenjiSimulationTests`・`HiraGenjiWeavePatternTests` と `ProjectEditorPreviewData` にある。色が38になると、**どの糸が同じ色かが
  変わり**、色以外の結果まで変わりうる。
- 色選択シート `ThreadColorSelectionView`: 適応グリッドに、色の丸・名前・`temporaryCode`、読み上げは「名前、仮コード…」。

## 2. すること（この順で。コミットを分ける）

### 2.1 まず試験を色の一覧から切り離す（色を変える前。結果は1つも変わらないこと）

- 上の `colors[$0 % colors.count]` の形を、**試験の中に書いた12個のIDの並び**（いまの `colors` と同じ並び）に置き換える。
  これで一覧が変わっても、どの糸が同じ色かは変わらない。
- この段階で全件を回し、**形状ハッシュ・カードの画素・どの試験の結果も変わらない**ことを確かめてコミットする。

### 2.2 38色にする

1. `ThreadColorCatalog.colors` を `docs/colours.md` の38色にする（並び・内部ID・名前・値は表のとおり）。
   - `temporaryCode` はやめ、店の番号を持たせる（例 `No.01`、限定は `限定`）。名前は `code` などに改めてよい。読み（すみれいろ）も持たせる。
   - 既定の色は **No.15 象牙 `zoge`**。
2. **古い12のIDは読み替える**（`docs/colours.md` の移し替えの表）。
   - `ThreadColorCatalog.color(for:)` と `contains` は、古いIDを渡されても新しい色を返す（読み替え表をデータとして持つ）。
   - 保存済みの作品は、開いたとき古いIDのまま正しい色で描かれ、次に保存したとき新しいIDで書かれる。
     （SwiftData の移行は要らないはず。要るなら理由を書いてから足す。）
   - 読み替えは永続する約束なので、表を消さない。
3. 色選択シート: 38色を店の番号順に並べる。色の丸・名前・番号。読み上げは「菫色（すみれいろ）、No.01」の形。
   薄い色（白土・象牙・白群など）にも境界線が見えること（いまと同じ）。
4. コードの中で古いIDを直接書いている所（1 の一覧）は、新しいIDに書き換える（読み替えに頼らない）。

### 2.3 見本配色を近い色へ（`BraidMethodCatalog`）

- 各見本配色の出所の写真（丸源氏 教科書 p.94、平源氏 p.96、八つ金剛 S/Z はレシピ本 p.54・55、返し組 教科書 p.38、
  丸四つ組 レシピ本 p.10 b、江戸八つ組 教科書 p.64）から**糸の色を測り**、38色から **CIEDE2000 でいちばん近い色**を選ぶ。
  - 1つの配色の中で違う色だった糸が、同じ色に集まったら、次に近い色で分ける（配色の柄を保つ）。
  - 写真が測れないときは、`docs/colours.md` の12色からの移し替えで決め、そう書く。
- 審査側が測った江戸八つ組の写真の色での結果（参考。worker は測り直してよい）:
  マゼンタ (0.84, 0.37, 0.56) → **No.05 藤色**（ΔE 18.5）、シアン (0.12, 0.58, 0.70) → **No.29 浅葱**（15.7）、
  黄緑 (0.65, 0.72, 0.53) → **No.27 青磁**（6.9。**黄で代用していたのが解消する**）、
  生成り (0.86, 0.83, 0.79) → **No.31 白群**（10.1。次は No.36 白土 11.6、No.15 象牙 11.8）。
- 各配色の説明文（「黄緑はカタログに無いので黄で代用」など）を、新しい色と測った値に合わせて書き直す。

## 3. 試験

1. 一覧は38色、IDが重ならない、並びが店の番号順、既定は `zoge`。値は `docs/colours.md` の表と一致（小数3桁）。
2. 古い12のIDがそれぞれ表の色になる。古いIDで保存した作品を開くと正しい色で描かれ、保存し直すと新しいIDになる
   （Task 058 の「前のスキーマの store を開く試験」の形を使ってよい）。
3. 見本配色は38色のIDだけを使い、配色の中で違う色だった糸は違う色のまま。
4. 2.1 の後の形状ハッシュは、2.2・2.3 の後も変わらない（色は形に効かない）。**カードの画素など色に効く固定値は変わる**ので、
   色だけが変わったことを確かめてから固定し直す（どの試験の値を固定し直したか報告する）。
5. ガードを通す。
