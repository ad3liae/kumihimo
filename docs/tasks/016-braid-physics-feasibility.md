# Task 016: 組み上がりを物理から解けるかの調査

- 状態: 未着手
- 優先度: 高（Task 008 以降より先。008 以降の中身がこの結論で変わる）
- 種別: **調査。製品コードを変更しない。**

## なぜ今これをやるか

Task 005E〜005I（丸源氏）と Task 007E/007F（平源氏）で、**1つの組み方を実物へ合わせるのに
10段階前後かかる**ことが分かった。資料写真を測り、定数を導き、対照実験で裏を取る。この
密度でやったからこそ信用できるものになったが、**Task 008〜014 の7本に同じことを繰り返すのは
現実的ではない。**

一方、この2つのタスクは副産物として**判定の道具**を残した。

- 正規化した並置による目視の計数（Task 005I）
- シルエットのさざ波（周期が1手と一致するかの確認つき）と較正式 σ(%) = 9.55 × 頂
- 単色の行に沿った輝度変調
- 配色だけを変えて構造を検証する対照実験（3件、いずれも合格）

**「物理で解いた結果が正しいか」を判定する装置がすでにある。** 判定できる状態で作れるので、
いまが検討の時期である。

## 決定的に効く前提

**組み上がりの形は配色に依存しない。** 色は解いたあとのメッシュへ塗るだけである。したがって
シミュレーションは**組み方ごとに一度**解けばよく、実時間で走る必要がない。事前計算して
結果を焼き込めばよい。この前提が成り立つ限り、要求される性能は問題にならない。

**この前提が崩れる材料があれば、その時点で報告すること。**

## 入力と出力

**入力は物理量と組み方だけとする。**

- 糸の太さ（1種類。太さの違う糸は扱わない）
- 糸の曲げにくさ、糸どうしの接触
- 張力（玉の重さ、吊り重り）
- 移動規則（すでに3資料で照合済み。`HiraGenjiWeaveDerivation` ほか）
- 台の形（丸台。16本なら4面×4本）

**出力は形だけとする。** 断面の輪郭、1手あたりの送り、糸の通り道、表面の起伏。

**現在コードにある形の定数は、1つも入力にしないこと。** それらは出力として再現できるかを
測る対象である。入力に混ぜたら調査が無意味になる。

## 再現できるかを測る対象（既知の実測値）

丸源氏（Task 005I まで）

| 量 | 値 | 出所 |
|---|---|---|
| 山形の密度 | 紐幅あたり 1.8〜2.15 | 実物写真（2通りの読み） |
| `patternAspectRatio` | 0.65（傾き 57.0度） | 上の両方を満たす値 |
| 面の列数 | 8 | Task 004 で実物3本と照合 |

平源氏（Task 007E まで）

| 量 | 値 | 出所 |
|---|---|---|
| 断面の幅÷厚み（平均面） | 3.3359 | 周長＝糸16本ぶん、厚み＝糸2本ぶんを解いた値 |
| 1手のピッチ÷紐幅 | 0.3665 | bookA p96 / bookB p23 の実測 |
| 畝の高さ（半厚比） | 0.45 | シルエットのさざ波と物理の重なり |
| 断面の分割 | 表6・裏6・左縁2・右縁2、弧長で等分 | 断面の糸の本数 |
| 横糸の経路 | 面の中央に一度も浮かない | bookA p97 の対照実験3件 |

## この調査が解くべき絡まり（Task 005J 段階2b、2026-09-06 追加）

**畝の高さと模様の縦横比は、実物写真からは分離できない。** 写真から測れるのは
「見かけの山形密度」という両者の組み合わせ1つだけで、片方を動かせばもう片方も動かさないと
写真に合わなくなる。丸源氏では次のとおり。

  頂 0.12（現状）・aspect 0.65   見かけの密度 2.17   写真の帯（1.8〜2.15）の中
  頂 0.353・aspect 0.65          見かけの密度 2.70   帯の外。戻すには aspect 0.75 付近が要る

0.353 は平源氏で決めた 0.45 糸幅ぶんを半径比へ直した値である。**物理はこれを指し、写真は
反対を指す。** 手で合わせ込む道では、この2つを独立に決める材料が無い。

**物理から解けば両方が独立に出るので、この絡まりは自然に解ける。よってこれを解けるかどうかが、
この調査が成立するかの判断材料の1つである。** 段階2（丸源氏を1つ解く）で、`crestHeightRatio`
と `patternAspectRatio` に相当する2つの量が**それぞれ独立に**出てくるか、そして両方を入れた
ときの見かけの密度が写真の 1.8〜2.15 に入るかを見ること。

なお **016 の結論が出るまで、丸源氏の `crestHeightRatio` と `patternAspectRatio` の
どちらも動かさない**（`docs/architecture.md`「畝の高さと模様の縦横比は、実物写真からは
分離できない」）。

## 段階

各段階の終わりに報告して止まる。承認を得てから次へ進む。

### 段階1: 何を解くかを決める（実装しない）

- 糸を何として表すか（中心線＋太さの鎖か、他か）。候補を2つ以上挙げ、選んだ理由を書く。
- 接触をどう扱うか。**貫通を許さないことが要件**である（第1版の平源氏が穴を開けた件と同じ轍）。
- 静的な釣り合いを解くのか、動かして落ち着かせるのか。
- 1つの組み方を解くのにどれくらいかかる見込みか。事前計算なので分単位でも構わない。
- **既知の値のうち、どれが「解けば出てくるはず」でどれが「出てこないはず」かを先に述べること。**
  あとから理由を作らないため。

報告して止まる。

### 段階2: 丸源氏を1つ解く（使い捨ての試作）

- **製品コードへ入れない。** Kumihimo ターゲットの外に置くこと。言語・環境は問わない。
- 移動規則を与えて解き、上の丸源氏の3つの量を測る。
- 測り方は既存の手順をそのまま使う（`.build/task007e-screenshots/modulation-procedure.txt`、
  `stage5-measurements.txt`）。**新しい測り方を作らないこと。**

**打ち切りの条件。** 山形の密度と面の列数のどちらかが実測から ±25% を超えて外れ、
かつ入力の物理量を常識的な範囲で動かしても寄らない場合、**そこで止めて報告する。**
定数を足して合わせにいかないこと。

報告して止まる。

### 段階3: 平源氏も解く

同じ仕組みに平源氏の移動規則を与える。**仕組みを組み方ごとに変えないこと。**

- 断面が自然に潰れるか。幅÷厚みが 3.34 付近に出るか。
- 1手のピッチ÷紐幅が 0.3665 付近に出るか。
- **横糸が面の中央に浮かないか。**これは色を付けずとも糸の通り道で判定できる。

**丸源氏と平源氏の両方が出て初めて、この道は成立している。** 片方だけなら、それは物理では
なく当てはめである。

報告して止まる。

### 段階4: 製品へどう載せるかの設計（実装しない）

- 事前計算の結果を何として持つか。どこで解くか（開発時に焼くか、初回起動時か）。
- 既存の `MaruGenjiSurfaceMeshGenerator` / `HiraGenjiSurfaceMeshGenerator` をどうするか。
  **いきなり置き換えないこと。** 既存の見えが崩れないことを保証する道筋を示す。
- Task 008 以降の7本を、この仕組みでどう追加するか。1本あたり何が必要になるか。

報告して止まる。**ここまでが調査であり、実装は別タスクとする。**

## やらないこと

- 製品コードの変更（段階1〜4のすべて）。
- 既存の定数を入力に使うこと。
- 新しい判定方法を作ること。既存の手順を使う。
- 合わないときに補正項を足すこと。合わないなら止めて報告する。
- 太さの違う糸を扱うこと。作者は同じ太さの糸で組む。

## 受け入れ

段階4まで到達した場合、**「この道は成立する／しない」がその根拠とともに書かれていること。**
成立しない結論でも、それが根拠つきで示されていれば成功とする。**Task 008 以降を手で
合わせ込む道で進める判断ができるようになるからである。**
