## 2. 追補1: 近傍の頂点と、先端を覆う面を区別する

対象: `KumihimoTests/RoundTube16StrandTipTests.swift` の
`everyLapTipEndsBeneathAnotherStrandWhileItsEndStaysOnTop`、特に `highestOther`（69〜86行）。

現状は、先端の周囲0.03以内で別セグメントの頂点を探し、その半径が先端より大きければ通る。
しかし**隣に高い頂点があっても、先端の位置を三角形が覆っているとは限らない**。
逆に頂点が近くになくても、三角形の内部がその位置を覆う場合がある。
本体の端で行う0.01以内の検査も同じ制約を持ち、候補がなければ `-infinity` のまま通る。
また `segmentIndex` が違うことは、`threadPosition` が違うことと同じではない。

**今の試験は近傍の高さの検査であり、名前と報告の「先端が隠れる」を保証していない。**
これは現在の先端が露出しているという指摘ではなく、今回追加した重要な回帰検証の不足である。

修正すること:

1. 製品が生成したメッシュの三角形を使い、選んだ先端の**同じ長手位置・周方向位置**で外から当たる面を調べる。
   半径方向の線と三角形の交点など、実面への交差で判定する。近傍頂点の最大値を遮蔽に読み替えない。
   既存の `SurfaceOpacityAudit` や八つ金剛の実メッシュ照合の考え方は使えるが、共通基盤の全面改修は不要。
2. 先端の頂と、本体端の頂を維持して検査し、可能なら先端の幅方向にも少数の代表点を足す。
   覆う側と覆われる側のセグメント・糸IDを記録する。同じ糸の別区間だった場合は区別して説明する。
   検査した点での主張に限り、全幅・内部経路まで証明したとは書かない。
3. 小さな人工例で、**近くに高い頂点があるが線を覆わない面は非遮蔽**、
   **頂点は遠いが三角形の内部が線を覆う面は遮蔽**と判定できることを確認する。
   正常に成功する試験として書き、意図的に試験を落として診断収集を発生させない。
4. 三角形の候補分け等は一度だけ行い、全三角形の探索を各点ごとに繰り返して試験を重くしない。

修正した検査が現行形を通れば、**製品コードを変えない**。
実際に覆われない箇所が出た場合だけ、点・糸ID・局所画像を示し、完了条件への影響を報告する。
その場で大きな形状変更や新しい候補探索に広げない。
