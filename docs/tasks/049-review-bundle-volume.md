コードと画像から、次を次案の検証対象とする。

1. **長い一定断面がある。** `RoundTube8Bundle.lens` は0.25〜0.75サイクルで rising と falling がともに1になる。
   この区間で `halfWidthInColumns` と `heightFraction` は一定。長手に0.5サイクル＝約0.404Dの一定区間を持つ。
   横断面には丸みがあるが、長手中央の高さの変化はない。この形が均一な小判形の見え方に寄与すると考える。
2. **覆いを幅で確保している。** 049では下地露出を減らすため腹の半幅0.60を採った。
   幅と高さが同じ `lens` に結び付くため、覆いの幅を保つと広い天井も残る。幅・高さ・潜る長さの役割を分けて調整する。

   原因が周波数、法線、UV、縮小時の干渉のどれかは未特定。糸筋の本数を増やすだけで解消したとはしない。

前回の049指示も寸法・傾きの比較を中心にし、一定断面の長さと、見える端がどう隠れるかを十分な受け入れ条件にしていなかった。

## 3. 束の高さと隠れ方を作り直す

### 3.1 形を先に比較する

照明・カメラ・紐幅を同一にした基準と、まず1〜2案の製品レンダーを作る。
生成りで微細な糸筋を一時的に外した診断用表示と、通常の材質を両方見る。診断用条件は最終製品へ残さない。
素材を外したときにも、腹・肩・潜り込みの違いが見える案を進める。

**推奨する最初の変更**: 幅を保つ関数と長手の高さの関数を分け、現在の長い高さ一定区間を、
滑らかな山と下りへ置き換える。非対称の滑らかな曲線など、少数の値で記述できる形でよい。
最大高さの点をどこに置くか、隣に押さえられる部分をどう低くするかを実物の読みと比較する。
最大高さだけを大きくすることを目的にしない。各束が丸い団子に離れず、幅を持った糸束として接する形にする。

- 横断面の丸みと、長手のふくらみを別に確認する。中心線の高さ・代表的な横断面を製品の形から図示する。
- 表へ出る側から腹を経て、隣の下へ滑らかに沈む。可視部分の端は、隣の束が遮ることで終わるよう調整する。
  両端の丸い閉じた輪郭が全て見える塊を並べる形を避ける。
- 先端を尖らせたり細めたりする処理は、主に隠れる範囲で行う。見える面に針状の先端や細い隙間を作らない。
- 下地を隠すための幅は、必要なら潜る部分で確保する。見える腹を一律に広げることだけで覆いを解かない。
- 光を受ける面から肩、谷への変化を作る。紐の外周は滑らかにつながりつつ、束のふくらみが読めること。
  外周の振幅から内部の谷の深さを直接決めない。

既存の `<1%` 下地露出の回帰検査は維持するが、露出率だけで候補を選ばない。
下地露出、穴、潜り込み、見かけの長さ・幅・傾きを同時に比較する。断面値は写真から直接観測した値とせず、描画上の選択と記録する。

### 3.2 一覧と立体に同じ形を適用する

主な対象は `Kumihimo/Domain/RoundTube8SurfacePattern.swift` の `RoundTube8Bundle`、
`RoundTube8SurfaceMesh`、`RoundTube8ThumbnailView.swift` 内の描画である。
形を表す値・関数は共有し、`standingFraction` と実際の頂点・法線、一覧の可視面の判定をそろえる。
追加した値が一覧の画像キーから漏れないようにする。キャッシュと最新配色のローダーの動作を保つ。
必要な箇所の分割数を調整する場合は、頂点数と生成費用を示し、形の精度に必要な範囲に限る。

## 4. 糸筋は面の流れに沿わせる

形の候補を選んだ後、同じ形で材質を比較する。

- 糸筋を束の長手方向へ追え、腹から潜る部分まで面に沿って続くようにする。
  局所的な撚りの斜め筋と、束全体の長軸を区別する。全ての線を同じ直線に固定する必要はない。
- 網目状の見え方がどこから来るか、色・陰影マップ、法線、粗さを個別に外した小さな比較で切り分ける。
  写真の細かさだけを目標に周波数を上げない。通常の表示寸法でも糸の方向が残り、ちらつきや干渉模様が目立たない範囲を選ぶ。
- 実メッシュの接線とUVに対して、糸筋を描く向きと法線の向きが一致するか確かめる。
  広さが変わる新しい束へ、旧形状用の一定係数を無条件に当てはめない。
- 境界の陰影は実際に隣へ沈む部分を強調する。束全体を均一な黒い輪郭で囲まない。
- 8本側だけを調整する。16本の共通素材の既定値は維持する。新しい外部依存や繊維メッシュの大量生成は不要。

## 5. 一致試験の新しい除外条件を修正する

049で下地の共有境界判定は限定されたが、別の除外に問題がある。
`RoundTube8CardAgreesWithSolidTests.theCardShowsWhatTheSolidShowsAcrossARepeat` の
run同士が不一致のときの追加条件:

`mine == nil || theirs >= (mine ?? 0) - 1e-6`

`theirs` は全メッシュの交点の最大半径、`mine` はその同じ交点集合からカードが選んだ束だけを抜き出した最大値である。
**全体の最大値は部分集合の最大値以上なので、この条件はrun同士の不一致を事実上すべて除外する。**
カードが誤った糸を選んでいても通り得る。10%の除外率上限だけでは、狭い範囲の回帰を検出できない。

- この条件を除去し、解析形状と三角形の近似差による例外を残すなら、独立した誤差の根拠と局所条件に限る。
  大きな高低差がある内部点や、誤った束ID・リピートを選んだケースが除外されないこと。
  交点がない `nil` 自体を例外の根拠にしない。
- 既知の不一致4点は、場所、解析側で上にいる束、三角形側で上にいる束、半径差、境界からの距離を調べる。
  必要なら形の分割精度を直す。例外を追加しただけで検査を通すことを目的にしない。
- 製品を書き換えて意図的に全件を落とす手順は不要。正しいケースは通り、内部点で別の束・別リピートを選んだ人工例を拒む小さな回帰試験を追加する。
- 049報告のS 32,652/Z 32,493等は、ログ上は外観変更前に数えた値であり、文書にも「改修前」とある。
  **最終形状・最終判定で件数を取り直し**、解析形状による除外、下地境界、比較済み、不一致の内訳を報告する。

形の変更に合わせて検査の正当性を保つための修正であり、UI確認の範囲を広げるものではない。
