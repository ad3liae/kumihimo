## 1. 実際に見える糸を一致させる

現行カードの到着順で全輪郭を塗り重ねる方法は、立体の高さによる隠れ方と一致しない。
先に実際の生成メッシュでこの不一致を再現する小さな回帰試験を置く。

審査側の独立計算による再現候補（詳細・計算の限界は親タスク末尾）:

| 項目 | 条件 |
| --- | --- |
| 組み方 | S、8色識別 |
| 区間 | 同じ場所に1サイクル差で着く先着・後着の2区間 |
| 長手位置 | 先着の開始から1.10サイクル（後着の開始から0.10） |
| 周方向 | その場所の中心から−0.18列 |
| 実装の分割を再構成した半径 | 先着 約0.41103、後着 約0.38977（頂0.48） |
| 不一致 | 先着の面が外側にあるが、カードは後着の色を上塗りする |

先着の開始から1.30サイクル・周方向−0.42列でも同じ不一致を得た。
例えばSの列0は、現行の到着位相では先着の開始が−0.75、後着が0.25サイクルとなる。
端の切り取りを避け、中央のリピートへ移して確かめる。報告中の近似値をそのまま期待値に固定せず、実メッシュで糸IDと前後関係を判定する。

実装方法は次の性質を満たす小さなものを選ぶ:

- 各表面位置で外側に見える区間を決める規則を、カードと立体で揃える。
  立体の可視面を展開図へ反映する方法、または両者に共通の可視領域を与える方法などが考えられる。
  到着順を維持するため形を変えるなら、その順序が重なる領域全体で成り立つことと、形の退行がないことを示す。
- 色ではなく糸ID・区間で判定する。同色の糸が隣接する場合でも処理を変えない。
- 新しい検査は、セルの色メタデータや畝の頂だけの比較で済ませない。肩の前後と両脇を含め、S/Z、長手周期と周方向の継ぎ目を対象にする。
- 立体の透視画像と展開図の画素を直接一致させるのではなく、同じ長手位置・周方向へ対応づけて、見える糸の所属を検証する。
  実際の三角形の表面とカードが使う可視領域を比べ、境界上の丸め誤差は限定して扱う。
- 外側の面を途中で覆う別の区間も含めて判定する。比較する2区間だけを見て可視と断定しない。

「後着がどこでも上」とする現行コメント・報告を、採用した実際の規則に合わせる。
幾何の交差線を描画上の近似として残すことと、実物の組みの先後を確定したことを混同しない。

## 2. カードの向きを外側から見た立体に揃える

現行の共通レイアウトは周方向が画面の下へ増える。立体の正面とは上下が反転するため、8本側の座標変換で揃える。
共通レイアウトの大きさ・リピート配置は利用してよいが、16本の見えを変えない。
S/Zの名称やレシピを交換する、手順表を変える、詳細のカメラを反転する方法で解消しない。

検証画像では、長手の正方向と周方向の増える向き、立体正面に対応する展開図の領域を注記する。
同じ側の端を揃えて、S/Zそれぞれの糸束の傾きと8色の並びを確かめる。
これはアプリ内の座標の対応を確認するための注記であり、写真のどちらの端が組み点かを確定するものではない。
注記や比較用の座標は本番UIに出さない。

### 2. 不一致の再現と、直った結果（実メッシュ）

**試験の作り**: 実際に生成したメッシュの三角形へ、軸から外向きに光線を出し、**当たった三角形のうち一番外側**がどの糸束（または下の升）の頂点かで、立体に見えているものを決める
（`Solid.outermost`。三角形は長手×周方向の格子に振り分けて探すが、振り分け無しの総当たりと結果が一致することを確かめた）。
カード側は、カードが実際に描く画素の表（`RoundTube8CardImage.shownMap`）を使う。**色は比べず、糸束（リピートとセルの番号）で比べる。**

- **再現**（修正前のカードの塗り方をそのまま試験に書いて、実メッシュで）: S、列0、先着の開始から 1.10 サイクル・中心から −0.18 列の位置で、
  **立体は先着の糸束（半径 0.41103）、カードは後着の糸束**。1.30 サイクル・−0.42 列でも同じ（半径 0.38191）。**審査の独立計算の値と一致した。**
  （開始から −0.75 サイクルの糸束は、リピートの端を避けて2つ目のリピートの1行目として取った。）
- **修正後**（`thePlacesTheReviewFoundShowTheSameThreadOnTheCardAndTheSolid`）: 同じ2か所で、立体もカードも**先着の糸束**を見せる。
- **1リピート全体**（`theCardShowsWhatTheSolidShowsAcrossARepeat`、S と Z）: カードの画素を1つおきに、両脇・肩の前後・周方向の継ぎ目・リピートの継ぎ目を含めて比べ、
  **比べた S 16,128 点・Z 16,266 点で不一致 0**。
  **見逃した点**: S 768 点（4.5%）・Z 630 点（3.7%）。ここでは、メッシュの平らな三角形が滑らかな面より内側に入るので、どちらが上かが三角形の切り方で変わりうる。
  具体的には、一番上の糸束の「メッシュの標本点で取った高さ」が次の糸束と 3% 以内のところ、一番上の高さが谷底から 3% 以内のところ、
  糸束の幅の端の最後の標本より外（輪郭そのものが弦になる）、到着から2つ目の標本より手前。
  **最初にこの帯を入れずに回すと、不一致は S 32 点・Z 28 点で、全てこの帯の中だった**（幅の外側1割か、到着の直後）。上限（見逃しが全体の1割未満）も試験している。
- **修正前との差**: 見える糸束が変わったのは、カードの画素のうち **S 532/16,896（3.1%）、Z 428/16,896（2.5%）**（一時的な試験で数えた。コミットしていない）。
- **向き**（`theCardRunsRoundTheBraidUpItsFaceWithTheFrontInTheMiddle`）: カードの中央の行が turns 0（立体の正面）で、上へ行くほど turns が増える。
  糸束の頂が長手に進むと周方向に動く向きが、立体の正面とカードで同じ（S も Z も）。
- **立体は不変**: `theMeshIsTheShapeItWas` のハッシュ `0xfbb4_48c0_8f4a_7fdd` が通る。途中で高さの式の掛け算の順番を変えたら浮動小数の丸めでハッシュが動いたので、
  **元の書き方に戻した**（丸め以外に形の違いは無い）。したがって立体の画像は作り直していない。

**実際の規則**: その場所に届く糸束のうち一番高く立つものが見え、どれも届かなければ下の升が見える。
**「後着がどこでも上」ではない**——先着の畝の頂では、後着が肩まで立ち上がった先では後着が上だが、次の到着の直後の先着の脇では先着が高く、見える。
**交わる線は描画上の近似であり、実物の組みの先後を決めたものではない。**
