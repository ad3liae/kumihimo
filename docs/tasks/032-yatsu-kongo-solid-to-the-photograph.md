既存の仕組みに足りなかったものが2つあり、**どちらも「倍率の違うものを目で比べない」ため**である。

1. **参照写真を紐幅に揃える。** これまでシートは写真を**シートの幅いっぱいに引き伸ばして**
   いた（パネルは等倍で置かれる）。八つ金剛の写真は紐が3本縦に並んでおり、そのままでは
   縮尺が合わない。`BraidComparisonSheet.reference(...)` を足した——**1本を切り出し、
   横倒しにし、紐幅がパネルの紐幅と同じ画素数になるように縮尺する**。
   `sheet(..., photographWidth:)` はその幅で描く。**既定は nil で、これまでのシートは

2. **2つのパネルの長手の縮尺を揃える。** `build` は新しい経路の窓を

   源氏2つではたまたま見られる長さになっていたが、八つ金剛では**新しい経路のパネルだけが
   倍以上長く**なった。**それぞれの全長のうち同じ割合**を取るように直した。

**`DRAW_SHEETS` は `xcodebuild` の環境変数では test プロセスへ届かない**（`TEST_RUNNER_` を
付けても届かない）。届く道は

    xcrun simctl spawn <UDID> launchctl setenv DRAW_SHEETS 1
    xcodebuild test ... -only-testing:KumihimoTests/BraidComparisonSheetTests \
      -default-test-execution-time-allowance 600
    xcrun simctl spawn <UDID> launchctl unsetenv DRAW_SHEETS      # ← 忘れないこと

**最後の1行が要る。** `launchctl setenv` は**その機体に残る**ので、外し忘れると

指示書の「シートは `DRAW_SHEETS` を付けたときだけ描かれること（既定の実行を重くしない）」は
**コード側では守られていて、機体側の環境で破れる。**

既存の doc comment に書かれている `DRAW_SHEETS=1 xcodebuild test ...` は、この環境では効かない。

### 測ろうとして採らなかったもの（**採らなかった理由ごと**）

- **構造テンソルによる「豆の長軸」**。ぼかしを変えても **±10° 以内で軸方向**を返し続ける。
  これは**筒自身の横方向の陰影と、糸の中の細い筋**を読んでいる。陰影を引いても変わらない。
  **採らない。**
- **色で豆を切り出す**。この配色は同じ色の糸を2本ずつ隣に置くので、**同じ色の単位が
  くっついて1つの塊になる**。出てくるのは豆ではなく**色の帯**（長さが紐幅の 0.74）。
  **採らない。**
- **紐を横切る向きの周期**（列の幅）。中心帯の幅（0.44 紐幅）が列の幅（0.383）と近すぎ、
  峰が立たない。**測れなかった。**

**単位について写真から動かずに出るのは「最短の歩幅」だけである。** 上の表はそれを使っている。

### S の測り直し（開いている2件のうち1つ）

**測り直して変わらなかった。** 色の周期 379.3 px ÷ 4 サイクル ÷ 幅 235 px = **0.403**。
**S が自分の中で辻褄が合わない件はそのまま残っている**（伸び 0.403 → 帯 46.5° に対し、
測った帯は 54.5°）。

**気づいたこと（判定の材料として）**: **もし S の色が3サイクルで回るなら**、
379.3 ÷ 3 ÷ 235 = 0.538 となり、そこから出る帯の角は **54.6°**——**測った 54.5° と一致する。**
だが導出は3を許さない（配色の周期が4、送りが3、4 と 3 は互いに素なので周期は4）。
**この一致は、どこかで4以外の数が効いていることを示唆する。合わせに行っていない。**

**指示側の測定との食い違い**（Z-a の帯: 指示側 43.0°、worker 51.0°）は
**worker の値を採った**。理由: worker の側は**升の肌理をぼかしてから**測っており、
ぼかしの強さを変えても読みが動かないことを確かめている（S は 55.0/55.0/54.5/53.5）。
ぼかさずに測ると升の格子を読んでしまう。

## 段階2 の結果: 仕分け

### 1. 導出から出るもの（**前提に直に関わる。判定が要る。直していない**）

- **単位の歩幅の傾き（36° 対 0°）。** **前提から直に出る差である。** 「面に見えるのは
  留まっている糸で、渡りは面に出ない」なら、留まっている糸は**紐の長手に走る**ので、
  単位は軸に平行になり、格子は傾かない。**一様な 36° の傾きへ寄せる道は、前提を曲げること
  以外に見つからなかった。よってここで止める。**
- **色の帯の角（8.0°）。** 031 から持ち越し。埋めるには測った伸びを動かすしかない。**止める。**

**ただし 1 の中に、前提を曲げずにできることが1つある。判定を仰ぐ。**

> **到着の位相を使っていない。** 前提はこう言っている——留まっている糸は
> **「到着の長手座標から出発の長手座標まで」**走る。**到着の長手座標は場所ごとに違う**
> （1サイクルの8つの手は別々の瞬間に別々の場所へ着く）。いまの立体は**全ての升の下端を
> `row × 1サイクル` に揃えており、この位相を使っていない。**
>
> S の到着の瞬間は場所 1〜8 で 2, 6, 4, 7, 1, 5, 3, 8（9 分の）。隣り合う列の差は
> **+4/9, −2/9, +3/9, −6/9, +4/9, −2/9, +5/9, −6/9**。
>
> - **これは「隣の列のずれ」の行そのものである。** 写真は煉瓦積みに見え、いまの立体は
>   升が揃っている。**位相を入れれば煉瓦積みになる。**
> - **ただし一様な傾きにはならない。** 位相から出る隣の列への歩幅は軸から **+65° と −55°
>   の交互**で、測った **+36° の一様**とは違う。**1周すると位相は戻るので、平均の傾きは 0
>   のまま**（031 で確かめたとおり）。
> - **これは前提を曲げることではなく、前提が言っていることを使っていないだけである。**
>   だから 2 でも 3 でもなく **1 に置き、作者の判定を仰ぐ。**
