## 1. 審査側が確かめたこと（色のデータは正しい。違うのは形）

### 色のデータは正しい

作者のスクリーンショットの模様図を画素で読むと、どの段も周方向に **青・緑・桃・白・青・緑・桃・白**、
1段おきに **桃・白・青・緑…** で、**緑はいつも青と桃のあいだにある。** 作者の配色（周方向に 桃・白・青・緑）とも、
教科書 p.64 の組みはじめ（スリット順に マゼンタ・生成り・シアン・黄緑）とも、**周方向の並びが同じ**である。
置換（057: 奇数 +2・偶数 −2）で回すと、1つの場所の色は周期ごとに2色を交互に取る（場所4なら 緑・白・緑・白…）。

**半ピッチの菱形の格子では、緑の粒に接するのは隣の列の、半周期ずれた粒だけで、それは青か桃である。
緑と白は接しない。** 作者の「緑の横はピンク」はこれである。

### 違うのは形

立体を拡大すると、**各列（場所）が紐の長さの向きに長い束の列になり、同じ列の次の束と頭と尾でつながって見える**
——緑の列は **緑・白・緑・白**、その下の列は **桃・青・桃・青** の縞になっている。八つ金剛の束の作り
（束は升を越えて長く、尾は後から置かれる束の下へ潜る。045〜055）をそのまま使っているからで、
**同じ列の上下（緑と白）がいちばん目立つ接し方になり、隣の列との接し方（緑と桃）が束の脇に隠れる。**
だから色の並びが違って見える。

教科書の写真は、**短い粒が菱形の格子に並ぶ**。粒は隣の列の粒と脇で接し、同じ列の粒とは先端で点で触れるだけ。

**審査側の粗い実測**（教科書 p.64、600 dpi。**worker は測り直すこと**）: 紐の太さ D ≈ 93 px。マゼンタと黄緑は
長さの向きに ≈ 47.8 px ＝ **0.51 D** ごとに戻る。1つの場所の色は2周期で戻るので、**1周期 ≈ 0.26 D**。
描いた面は **0.886**（009 の実測）——**立体の升は写真の約 3.4 倍長い。** 周方向の1列の幅は πD/8 ≈ 0.39 D なので、
写真の粒は **長さ 0.26 D ÷ 幅 0.39 D ≈ 0.7**、正方形か、やや平たい。

**つまり作者の2つの指摘は同じ1つのことである。** 粒を短く正方形に近くすれば、緑は桃と青に囲まれて見える。

## 2. なぜ江戸八つ組だけ形を変えてよいか（名前で分けない）

`BraidFamilyDrawing` の約束は「**形の値は族のもの、族は紐から読む、組み方の名前で分岐しない**」
（`check-braiding-is-general.sh` が見張っている）。江戸八つ組と八つ金剛はどちらも8本の筒である。

**紐から読める違いがある: 運びの向きが揃っているかどうか。** 八つ金剛は全糸が同じ向きへ運ばれる（1本の向きの
らせん、`columnsCarried` が1つの値）。江戸八つ組は2組が逆向きに運ばれる（逆向きの2本のらせん、009 で
`columnsCarried == nil`・`leanDirection == nil` になった）。**逆向きの2組が交わる紐は、目の詰んだ菱形の格子の
短い目になり、一方向のらせんは長く斜めの束になる**——これは紐の構造から出る違いで、名前ではない。

**推し: 族を「運びが一方向か、両方向か」で分ける**（例 `.roundTube(threads: 8, turning: .oneWay / .bothWays)`、
`BraidFamily.family(of:)` が導出から読む）。両方向の8本の筒に、**粒の形の値（`BraidFamilyShape`）**を持たせる。
描くコードは八つ金剛のものを流用してよいが、**形の値は別の組**にする。族を分けるのが重すぎるなら、同じ描き手の中で
「運びが両方向か」で形の値の組を選ぶ形でもよい——**どちらにしても名前では分けない。** 選んだ方と理由を書くこと。

丸四つ組（4本、全糸が同じ向きに2場所）は一方向で、今のまま。

## 3. 粒の形

- **升1つ＝粒1つ。** 粒は升（その場所・その周期）の中に収まり、**同じ列の次の升へ長く伸びない**。
  尾を後の束の下へ潜らせる作り（八つ金剛の 051）は使わない。
- **長さ（紐の向き）÷幅（周方向）は 0.7〜1.0**（作者「正方形に近い」、1節の実測）。**1周期÷D は写真から測った値を
  `.observed` で入れる**（測り方は `measurement-procedures.md` に足す。009 の 0.886 と同じ測り方で、写真と描いた面の両方）。
- 粒は**角を丸めた、ふくらんだ枕の形**（033 の「升の両端を丸くして粒に見える」が近い）。丸め・高さ・谷の深さは
  **写真に対して目で合わせた `.declared`** とし、そう書く。
- **半ピッチの菱形の格子**（隣の列は半周期ずれる）は今のまま。**粒の傾き**は付けないか、ごく小さく（付けるなら
  055 の向き＝運びの逆）。写真と並べて決め、決めた値を書く。
- 床（粒の隙間に見える色）は今の作りに従う。

### 1. 族を分けた（報告1）

**`BraidFamily.roundTube(threads:turning:)` に「運びが一方向か、両方向か」を足し、紐から読む**（`BraidTurning.of`）。
周期ごとに組みの手（詰めの `closing` は除く）の運びを短い向きで数え、同じ周期に逆向きがあれば `.bothWays`。
**半周（8場所の4場所、4場所の2場所）と動かない糸は向きを持たない**ので数えない——返し組の持ち替え（4場所）と
丸四つ組の運び（全部が半周）がこれに当たる。名前は読まない（`check-braiding-is-general.sh` 通過。`Domain/Braiding` には
注釈にも組み方の名前を書いていない）。

| 紐 | 読み |
| --- | --- |
| 八つ金剛 S・Z・返し | 一方向 |
| 丸四つ | 一方向（運びが全部半周で、向きが無い） |
| 江戸八つ（教科書の表・レシピ本 p.48 の表・名前を変えた同じ表） | 両方向 |
| 丸源氏（16本） | 両方向（組みの手が ±13 ノッチ） |

**8本の筒は2つの族を1つの描き手で描く**（`RoundTube8SurfaceMesh.family` と `.familyTurningBothWays`、形の値は
`.shape` と `.shapeTurningBothWays`）。**選んだ理由**: 分かれるのは形の値だけで、升（占有履歴）・半ピッチ・メッシュとカードの作りは
同じ。描き手を複製すると一方の直しが他方に届かない。一方、族を分けずに描き手の中で選ぶと、1つの族が2組の形の値を持つことになり、
「形の値は族のもの」（`BraidFamilyShape`）が崩れる。族が選ぶのは4つ——糸が何として見えるか（`RoundTube8SurfacePattern.bundle`:
束 `.standard` と粒 `.grain`）、1周期の長さ（`pitchOverDiameter(for:)`）、山の高さ（`runHeightOverRadius(for:)`）、
糸筋と陰の地図（`RoundTube8StrandTexture.maps(on:)`）。16本と4本の筒の族も `turning` を持つようになったが、描き方は変わらない。

横は半楕円。陰の地図も両端を同じに陰らせる（粒は何の下にも入らない）。

### 3. 1周期÷D（報告2）

`Scripts/task059/measure_grains.py`（測り方は `measurement-procedures.md`「粒を数えて1周期を読む」に足した）。

| | 紐の幅 | Task 054 の読み（009 の 0.886 と同じ） | 審査側の読み（色の周期 ÷ 2） | 粒を数えて |

### 6. 写真の格子は描いた格子と違う（**判断が要る**）
