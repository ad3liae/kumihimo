## 何を確かめるか

040 の `REST=held` は、乗った区間（自由部の固定端側で固定球に触れている区間）を settle でも動かさない。これは 040 の最初の意味
「縮めないが押されれば動く（`REST=still`）」からの**模型の変更**で、041-2 の 9 手目の詰まり（根元が頭に引きずられ、裏返った交差の下で
解けなくなった）を避けるために入れた。同僚（4 回目・12 回目の指摘）: 完全に動かさない拘束が**詰め直しを妨げている**可能性がある。
現行のピッチは 4.02／3.04 d で、旧結果の 4.8 d を理由に押し付け不足とは言えない。**この実験は「動かさない拘束が詰め直しを妨げて
いるか」を 1 条件の差で確かめる**——押し付け（A1）や固定を遅らせる（③）を入れるかは、結果を見て決める。

**1 条件にするために**: `probe.py` の送りは `REST` で分岐している（`REST=still` は固定部と芯だけを下げる旧方式に戻る。`send` の
`if not REST_HELD(): return super().send()`）。**両条件とも「組み上がり全体を一緒に下げる」現行の送りを使う**（送りの分岐を外す）。変えるのは
**乗った区間を射影（間隔・押し離し・台の押し出し）で動かせるか**だけ。縮めと置き直しを受けないのは両条件で同じ。

## 042-0. 検査器の縁側の角落としを直し、041 の結論への影響を確認する（最初に。これが済むまで 1 以降に進まない）

同僚の 12 回目の指摘: `follow.py` の `common()` は前後の**短い方の全長**で分割点を切っている（`hi = min(pre.u[-1], post.u[-1])`、
`U[U < hi]`）。その先にある長い側の角は落ち、最後の縁の点へ直結される。人工例（同じ球数・同じ両端・最大変位 0.2 d）:
更新前 `[(0,0,0),(1,0,0),(2,0,0),(2.01,0,0)]`、更新後 `[(0,0,0),(1,0.2,0),(2,−0.01,0),(2.01,0,0)]`、相手 `[(2,−0.01,−1),(2,−0.01,1)]`——元の折れ線は接触
（0 d）、`common()` 後は 0.00971 d、CCD は「安全」。**審査側も現行の `follow.py` で再現した**（更新後の角 u = 2.0416 が hi = 2.01 の先で落ちる）。

- **直し**: 分割点は**両状態の折れ点の和集合を切らずに全部**使う。短い方の全長を超えた u では、その状態の糸は縁にある（繰り出す前／
  取り込んだ後の材料は縁の点にある）ので、**その状態を縁の点で止める**（`np.interp` の端の値そのまま）。審査側が人工例で確かめた:
  この作りで更新後の距離は 0 d、CCD は「検出」。取り込み（後が短い）の向きも同じ。
- 直したら `ccd_check.py` にこの例（繰り出し・取り込みの両向き）を足し、既存の例が全部通ることを確かめる。
- **041 の結論への影響を確認する**: 直した検査器で、(a) 3・6・7・31 手目（`.build/task041/base` と `start-h31.pkl`）を再検査、(b) 現行の
  上限つき 48 手（`.build/task041/cap48` の pickle）を検査だけで再生して全部の線分対を検査、(c) 040 の基準結果 48 手も同じく。(b)(c) は
  各 30〜45 分。**通り抜け・未確定が出たら 2 状態を保存して報告し、041 の該当する結論を「保留」に戻す**（041 の状態の行と 040 の現行仕様 10 に
  審査側が書く）。出なければ「縁側の角も残した検査で通り抜け無し」と初めて言える。

## 042-2. 送りを共通にした held／still の比較

1. **`REST=still` の送りを現行の送り（全体を一緒に下げる）にする**（`probe.py` の `send` の分岐を外す。`REST=held` の挙動は変わらないことを、
   1〜4 手目の pickle が cap48 と球ごとに一致することで確かめる）。
2. **`REST=still` を検査つき・上限 d/4 で、まず序盤**: 1〜12 手目を回し、041-2 で `REST=held` を入れる原因になった詰まり（9 手目、送りの中の
   張りで残差 0.33／0.40、0.4 d の貫入）が**上限つきで消えるか**を確かめる。詰まり（settle の上限到達が続く、(a) > 0.02 d、止まる条件）が
   出たらそこで止めて報告（held を入れた理由がまだ生きている、が答え）。
3. 通れば **48 手**（検査つき、上限 d/4、1 手ずつ前で、`PICKLE`）。
4. **両条件を並べる**（042-1 の測り方で。ピッチはサイクル単位、実測値と変更内容をそのまま。1 件から誤差幅を出さない）: ピッチ、固めた球、
   乗られて固まらない球、外径、断面（幅・厚み・比）、1 d の高さの球、交差の数と反転（追跡の未確定は別欄）、(a)、通り抜け・未確定、
   上限が働いた手と球数、settle の上限到達、時間。
5. 乗った区間が settle で**どれだけ動いたか**を still で測る（各手、乗った区間の球の変位の最大と中央値。held では 0）。「詰め直し」が
   起きたなら、どこで（天辺／脇／根元）起きたかを 1 d の高さの球数の変化で示す。

## 042-3. 結果を見て次を選ぶ（審査側と同僚）

- still が序盤で詰まる → held を入れた理由は生きている。次は固定を遅らせる（③）か、詰まりの正体（引きずり）を別に扱う。
- still が通り、断面・密度が held と変わらない → 動かさない拘束は詰め直しを妨げていない。次は A1（乗った球を下の球に触れるまで下げる、
  W の幾何）か③。
- still が通り、密になる（1 d の球数が増え、断面が縮む） → 拘束が妨げていた。次は still を現行仕様にして③へ。
- **どの場合も、指示書を書く前に同僚の答えを聞く。**

- 文書は現行仕様・観測結果・原因の仮説を分けて書く。数字は糸と人工の芯を分ける。
- product code に触れない。テストは走らせない。`.build/` の外に走りを置かない。docs と Scripts のコミットは分ける。
- 前で回す（10 分の上限、`PICKLE`/`RESUME`）。重い走りは 1 つずつ。
