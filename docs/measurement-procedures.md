# 実物の写真とレンダーを突き合わせる測り方

組紐の見た目を実物へ寄せる作業では、同じ量を何度も測り直す。手順が揺れると、前のタスクの
数値と今のタスクの数値が比べられなくなる。**ここを測り方の正本とする。**

各手順の出どころと生データは `.build/task007e-screenshots/`（平源氏）と
`.build/task005j-screenshots/`（丸源氏）にある。**`.build/` は git の管理外なので、
判断に効く事実はこちらへ写すこと。**

## 共通の原則

**較正式は組ごとに取り直すこと。引き写さないこと。** 断面も1手のピッチも組ごとに違う。
平源氏の畝の較正は直線 σ(%) = 9.55 × 頂 だったが、丸源氏は直線ですらなかった
（σ(%) = 17.31 × 頂^0.752）。引き写していれば大きく外していた。

**資料の数値へ ±15% で合わせにいかないこと。** 資料の値には糸の繊維のざらつき、カメラの
周辺減光、辺の取り方の振れが混じっている。**下限と目視で判断する。**

**手順が要求する条件は、フィクスチャを替えるたびに満たされているか確かめること。**
平源氏では主値の fixture B がたまたま単色だったため、「手元のフィクスチャで測る」ことと
「単色の行で測る」ことが一致していた。丸源氏へ数字を1つ並べたとき、この一致が偶然だった
ことに気づかず、2色フィクスチャの値を参考値として1年分の判断の隣に置いてしまった。

## 1. 長手方向の輝度変調

紐の谷の陰がどれだけ深いかを表す。

### 手順

1. スクリーンショットは**原寸**で測る（比較画像は縮小がかかって値が下がる）。資料写真は
   元の解像度で、傾きだけ補正する。
2. **単色の行**を選ぶ。行の中で色が替わると、形と無関係に値が上がる。
   - レンダー: 全糸を1色にしたフィクスチャを使う
     （`--ui-testing-hira-surface-plain` / `--ui-testing-maru-surface-plain`）。
   - 資料: 長手方向に1色で続く帯を目視で選び、その帯の内側だけを使う。
3. 各行について、紐の直線部の画素を取り、**RGB の単純平均**を輝度とする（重み付けなし）。
4. **平滑化はしない。**
5. その1次元配列の p95 と p5 から `(p95 − p5) / p95` を求める。
6. **行ごとの値の中央値**を代表値とする（平均ではない）。min と max も併記する。

### この指標が掛けられない帯

p95 で割るので、**p95 が小さい帯では発散する。** 黒や紺のように極端に暗い帯は分母が
小さいぶんだけ値が跳ね、明るい帯と並べて比べられない。単色で続くのがそういう帯しかない
資料は、この手順では測れない。除外して理由を書くこと。

Task 005J でこれにより bookA p94（丸源氏の完成写真）を外した。長手方向に1色で続くのは
黒の縁取りだけで、山形の側は白・橙・桃が交互に来るため単色の帯が取れない。

### これまでの値

  平源氏  baseColor のみ 0.463 → 両スロット 0.618（Task 007E 段階4a）
  丸源氏  baseColor のみ 0.489 → 両スロット 0.617（Task 005J 段階1）
  資料 平源氏  bookA p96 0.670 / bookB p23 #23 0.884
  資料 丸源氏  作者の真上から 0.738 / bookB p23 #24b 0.772・0.814

## 2. シルエットのさざ波から畝の高さを読む

**この手順は平たい紐にしか使えない。** 適用範囲を先に読むこと。

### 手順

1. 写真・レンダーの傾きを補正する（残差の高域抽出は緩やかな傾きを自動で落とすので、
   1度以下なら省いてよい）。
2. 列ごとに紐の上辺を求める。**輝度が「背景と紐の中間値」を下向きに横切る点**を線形補間で
   亜画素まで求める。
3. 1手のピッチ2つぶんの移動平均を引いて高域を取り出す。
4. その残差の σ と p95 − p5 を、1手のピッチに対する比で表す。
5. **残差の自己相関でさざ波の周期を求め、紐の構造の周期と一致することを必ず確認する。**

### 周期の確認は形式ではない。これが唯一の歯止めである

一致しなければ、測っているのは**糸のけばと背景のざらつき**であって形ではない。
これを飛ばすと資料から誤った値を読む。**2度助かっている。**

- Task 007E 段階5: bookB p23 の白い縁糸は σ 12.59%、周期は出るが r=0.16。頂 1.32 に
  相当する — 糸が自分の直径の1.3倍盛り上がることはない。周期の確認で失格にした。
- Task 005J 段階2: 丸源氏の資料4枚はいずれも周期を持たない（15px 以上のラグでの自己相関
  0.12〜0.41、レンダーは 0.98）。**にもかかわらず、その σ を較正へ通すと頂 0.045〜0.193 が
  返り、現在の値 0.12 はそのまん中に落ちる。** 周期を確認しなければ、4枚とも「0.12 で
  合っている」と答えていた。

短いラグ（15px 未満）の相関は隣の画素どうしの滑らかさであって構造ではない。**構造として
ありうるラグの範囲で見ること。**

### 較正

現在の値を含む3つ以上の頂でレンダーし、σ と頂の関係を実測して引き直す。**頂 0 でも
レンダーして、σ がほぼ 0 になること（測定の床が無いこと）を確かめる。** 床があるなら、
式の切片が実体なのか測定の癖なのか区別できない。

  平源氏  σ(%) = 9.55 × 頂        直線。頂 0.12 / 0.24 / 0.48 で確認。
  丸源氏  σ(%) = 17.31 × 頂^0.752  直線ではない。頂 0.00〜0.48 の8点、残差 0.044、
                                   頂 0 で σ = 0.02%。

### 適用範囲: 丸い紐には使えない（Task 005J 段階2、2026-09-06）

丸源氏で試して、**手順そのものが丸い紐に向かない**ことが分かった。良い写真が無かったので
はない。根拠が3つある。

1. **実物の外周が滑らかで、畝の列に見えない。** 拡大しても縁は1本の滑らかな紐である。
   丸い紐には糸が折り返す縁が無く、糸は斜めにシルエットを横切るだけなので、**滑らかなのが
   正しい可能性が高い。**
2. **シルエットの特徴が目と1対1に対応しない。** レンダーの端の波形の周期は1手ではなく
   **1手の 4/9**（141px に対し 62px）。平源氏では1手そのものだった。何を数えているのかが
   組ごとに変わる。
3. **較正が飽和する。** 丸い紐のシルエットは接線の包絡なので、畝が高くなるほど隣の畝の谷が
   隠れる。頂を2倍にしても σ は2倍にならない。逆に読むとき、上の方ほど分解能が落ちる。

**平源氏のシルエット法は、縁で糸が折り返す平たい紐だから成立した道具である。**
Task 008 以降で丸い組み方（八つ金剛、江戸八つ、八つ瀬、唐八つ、江戸源氏、方丈）の畝を
決めるときは、**この手順を最初から選択肢に入れないこと。** 別の観測量を先に探すこと。

## 2.5 レンダーのスクリーンショットから幾何量を読むときの遠近法の補正

**レンダーのスクリーンショットで「紐幅あたりの何か」を数えるときは、模様が手前の面にあって
カメラに近いぶん拡大されている。** 紐幅は最も広いところ、すなわち軸と同じ奥行きで測るのに
対し、模様は手前の面で測るためである。

  倍率 = カメラ距離 ÷ (カメラ距離 − 外半径)

丸源氏では 4.4 ÷ (4.4 − 0.52) = 1.135、つまり**見かけの密度が 14% 低く出る。**

**補正せずに写真と比べると模様が過密に見え、縦横比を下げて合わせたくなる。それは Task 005H
の失敗の再演である。**

Task 005J 段階2b は当初この補正を欠き、1.87 / 2.06 / 2.21 と報告した。補正すると
2.12 / 2.37 / 2.58 で、幾何から直接出した 2.14 / 2.37 / 2.59 と 0.6% で一致する。
**スクリーンショットから幾何量を読んだら、必ず幾何と突き合わせて裏を取ること。**

平たい紐を正面から見る場合は、面も縁も同じ奥行きにあるのでこの差は出ない。**丸い紐だけの
問題である。**

## 3. 正規化した並置による目視の計数（Task 005I）

山形の密度のように「1紐幅あたりいくつ」で表せる量は、**紐幅を揃えて並べて数える**のが
いちばん確かである。

1. レンダーと資料を、**紐幅が同じ画素数になるよう**それぞれ拡大縮小する。
2. **同じ紐幅ぶんの長さ**を切り出す（Task 005I は 4.5 紐幅ぶん）。
3. 数える。

**色の周期と形の周期を取り違えないこと。** 自己相関だけに頼ると、配色が2手ごと・3手ごとに
繰り返す資料では、形の周期ではなく配色の周期を拾う。Task 005J 段階2 で bookA p94 の山形を
自己相関で読むと 140px（配色の周期）に見えるが、拡大して数えると 35px（形の周期）だった。
**必ず拡大した画像で数えて裏を取ること。**

平源氏で単色フィクスチャを足したのも同じ理由である。縁の色が目ごとに変わると、形と無関係に
シルエットの測定点が動き、周期が1手ではなく配色の2手周期になる。

## 4. 比較画像の作り方

段階ごとに、判断の根拠を1枚で見られるようにする。

- 紐幅を揃え、同じ紐幅ぶんの長さを並べる。
- 各段に**測った値を併記**する。
- レンダーの前後と、資料を**同じ画像の中**に置く。別々の画像だと目視で比べられない。
- 資料を外した場合は、外した理由を画像の中に書く。
